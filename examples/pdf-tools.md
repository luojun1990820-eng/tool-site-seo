## 1. Vet — 两个候选，一否一留

### A. 全能 PDF 工具箱（merge / split / compress / word / jpg / sign）

| 3 | 单次访问价值 | 15 | ⚠️ 免费工具类 CPC 低，RPM 估 $2–4 | 3 | 9 |

### B. PDF → Markdown（面向 AI / RAG 工作流）

| # | 维度 | 权重 | 证据 | 分 | 加权 |
|---|---|---|---|---|---|
| 1 | 搜索需求 | 15 | ⚠️ "pdf to markdown" 增长中，量级小于 merge 但趋势向上 | 4 | 12 |
| 2 | 词簇广度 | 10 | pdf to md / 保留表格 / 扫描件 OCR / 批量 / API | 4 | 8 |
| 3 | 单次访问价值 | 15 | ⚠️ 开发者受众，CPC 高于通用工具；可接 Pro 批量 | 4 | 12 |
| 4 | SERP 竞争 | 10 | ✅ 多为开源项目页（marker、docling）与博客，缺少打磨好的在线工具 | 3 | 6 |
| 5 | 差异化空间 | 15 | 可做：纯浏览器内处理（不上传）、表格保真、批量、离线 | 4 | 12 |
| 6 | AI 截流风险（逆向） | 10 | ✅ AI 能讲"怎么做"，但做不了转换本身，必须用工具 | 3 | 6 |
| 7 | 建站成本（逆向） | 5 | pdf.js 抽取 + 版式启发式，中等 | 3 | 3 |
| 8 | 维护成本（逆向） | 5 | PDF 千奇百怪，抽样回归必需 | 3 | 3 |
| 9 | 外链潜力 | 10 | 开发者会引用工具与数据 | 3 | 6 |
| 10 | 回访性 | 5 | 批量作业会反复用 | 4 | 4 |
| | **合计** | 100 | | | **72 / 100** |

**结论**：60–74 → **先做单页 MVP**，进前 20 再铺页面。

**盈亏平衡**

```
月收入 = 30,000 PV × $5 RPM / 1000 = $150
月成本 = (40h 建站 + 4h×12 维护) × $15/h / 12 + $10 托管 = $120
要求：150 ≥ 120 × 2 = 240  →  不通过（缺 $90）
需要约 48,000 PV 才过 2 倍线
```

⚠️ 这是最该被看见的一行：**72 分通过的选题，第一年可能过不了盈亏线。** 三条出路，选一条写进结论：

1. 接受它是引流资产，另有主产品承接（不指望广告）
2. 加第二条收入：Pro 批量 / API（开发者付费意愿高于广告 RPM）
3. 缩成本：纯前端 + 静态托管，建站压到 25h 内

## 2. Spec — B 的页面规格

### 2.1 页面清单

| 类型 | URL | 目标词 | 搜索量 | 独有内容来源 | 优先级 |
|---|---|---|---|---|---|
| 工具页 | `/pdf-to-markdown` | pdf to markdown | ⚠️ 待测 | 算法说明 + 表格保真实测 | P0 |
| 工具页变体 | `/pdf-to-markdown/scanned` | scanned pdf to markdown | ⚠️ 待测 | OCR 管线差异 | P1（有量才做） |
| 工具页变体 | `/pdf-to-markdown/with-tables` | pdf to markdown table | ⚠️ 待测 | 表格抽取对照样例 | P1（有量才做） |
| 对比页 | `/alternatives/marker` | marker alternative | ⚠️ 待测 | 逐项实测（在线 vs 自建） | P2 |
| 解释页 | `/what-is/markdown-for-rag` | markdown for rag | ⚠️ 待测 | 为什么要转、格式差异 | P2 |
| 目录页 | `/tools` | pdf tools | — | — | P1 |

**明确不做**：merge / split / compress / sign —— 那是 A 的战场，做了就是在别人的强项上排第 9。

### 2.2 URL 与内链

- 子目录 `/pdf-to-markdown`，不用 `/tools/pdf-to-markdown`（一句话工具，扁平更好）
- 尾部斜杠：无；301 统一
- 无日期、无 ID、无参数页
- 每页入链 ≥3：`/tools` → 工具页 → 两个变体 + 解释页
- 面包屑：Home > Tools > PDF to Markdown

### 2.3 结果页索引策略（这个站的关键）

| 情形 | 处理 |
|---|---|
| 工具页首屏 | 服务端渲染：H1、方法说明、**一段示例 PDF 的转换结果**、公式/规则 |
| 用户上传后 | 结果只在内存里，**不产生 URL** |
| 分享结果 | 不做（涉及用户文件，隐私 + 无限 URL 空间） |
| 变体页 | 只有通过需求验证才建，且必须有自己的实测样例 |

**下限**：关掉 JS 后可见正文 ≥150 词。纯前端转换站最容易犯的错就是首屏只有一个拖拽框 —— 那是 0 词的 JS 壳，直接不合格。

### 2.4 组合页白名单

这个方向**不需要**大规模组合页（不像单位换算有几千个 X to Y）。白名单只有上面 2 个变体，条件是：

- 搜索量 ≥ __ 或 GSC 曝光 ≥ __
- 能写出该变体独有的实测差异（扫描件的 OCR、表格的合并单元格）
- 否则不建，宁缺毋滥

批次规则不适用（总量就 3–5 页），但 Gate 里的独有度仍要过 ≥40%。

### 2.5 sitemap

```
/sitemap.xml
├── sitemap-tools.xml        # 主工具 + 变体
├── sitemap-compare.xml      # alternatives
├── sitemap-explainers.xml   # what-is
└── sitemap-blog.xml         # 有内容才建
```

只放 200 + 自指 canonical + 可索引；`lastmod` = 实质变更日（换了抽取算法、更新了实测样例），不是构建时间。

### 2.6 工具页八块（填满后的样子）

1. **H1**：PDF to Markdown Converter
2. **工具本体**：拖拽区 + 粘贴 URL + 「处理在本地完成」提示（这是差异化，要写在首屏）
3. **示例结果**：一段真实 PDF 转出来的 Markdown，带标题层级与表格（服务端渲染）
4. **原理**：文本层抽取 → 版式重建 → 标题层级推断 → 表格识别；说明哪些 PDF 会失败（扫描件、多栏、加密）
5. **算例 3 个**：论文 / 财报 / 扫描发票，各给输入特征与输出片段
6. **FAQ 6 条**：会不会上传？表格保真吗？扫描件呢？有大小限制吗？能批量吗？和 marker 有什么区别？
7. **相关工具**：`/pdf-to-markdown/scanned`、`/alternatives/marker`、`/what-is/markdown-for-rag`
8. **最后更新**：2026-11-08

## 3. 进 Gate 前必须盯的三件事

1. **首屏无 JS 可读性** —— 纯前端工具的生死线，Gate #2
2. **示例结果必须真实** —— 编一个漂亮的 Markdown 示例，等于给用户假承诺，也过不了 E-E-A-T
3. **隐私声明** —— "文件不上传"要说清楚，否则转化率会被疑虑吃掉

## 4. 这个例子想说明什么

- A 的失败不是因为想法差，是因为**赛道已被占满且对手免费**
- B 通过评分，但**盈亏平衡第一次算不过**——这才是真实决策点
